使用 Xiaomi-Robotics-U0-4B，根据文字描述生成一张 1024 × 1024 的 RGB 图片。
示例通过命令行运行，文本到视觉 token 的生成和 Emu3.5 图像解码都由 PhyAI 完成。

## 准备模型

你需要 Linux、Python 3.12 或更高版本、`uv`，以及支持 CUDA 和 BF16 的 NVIDIA GPU。
安装时保留仓库对 Torch、Transformers 和 FlashInfer 的版本约束。在 PhyAI 仓库根目录执行：

```bash
uv lock
uv sync --locked
export U0_CHECKPOINT=/path/to/Xiaomi-Robotics-U0-4B
export U0_VISION_TOKENIZER=/path/to/Emu3.5-VisionTokenizer
```

将两个变量设为已下载的模型目录，后续生成命令在同一个终端运行。
如果已有配好的环境，激活该环境，再设置这两个权重路径。

U0 目录需要包含模型权重、`config.json`、`unis.tiktoken` 和 `unis_vision_tokens.txt`。
[Emu3.5-VisionTokenizer](https://huggingface.co/BAAI/Emu3.5-VisionTokenizer) 目录需要包含配置和模型权重。
文本分词使用的 `tiktoken` 随 `phyai-utils-tools` 一起安装。

## 生成图片

先用 `nvidia-smi` 查看 GPU 是否空闲，再运行：

```bash
PHYAI_FLASHINFER_WORKSPACE_BYTES=536870912 \
uv run --locked python examples/xiaomi_u0/run_xiaomi_u0.py \
  --checkpoint-dir "$U0_CHECKPOINT" \
  --vision-tokenizer-dir "$U0_VISION_TOKENIZER" \
  --prompt "A studio photograph of a ceramic teapot on a wooden table." \
  --output-dir ./outputs/u0-teapot \
  --seed 42 \
  --max-new-tokens 4169
```

打开 `outputs/u0-teapot/image.png` 查看结果。换一个提示词时，修改 `--prompt`，并为 `--output-dir` 指定新目录或空目录。

`PHYAI_FLASHINFER_WORKSPACE_BYTES=536870912` 将 FlashInfer 工作区设为 512 MiB。
默认的 128 MiB 不足以运行这个完整图像配置，估算显存时还要计入模型权重和 KV 缓存。
一张完整图片需要输出 4169 个 token，`--max-new-tokens` 至少设为这个值。

程序先生成 token 并关闭自回归引擎，再加载图像解码器，两个模型分阶段使用显存。

## 查看输出

输出目录包含以下文件：

| 文件 | 内容 |
| --- | --- |
| `image.png` | 生成的 1024 × 1024 RGB 图片 |
| `generated_ids.npy` | 输出 token，不包含提示词 |
| `generation.json` | 提示词、种子、后端、停止原因、token 数、图片尺寸和计时 |
| `input_ids.npy`、`unconditional_ids.npy` | 有条件和无文本输入的 token |
| `tokenizer_mapping.json` | 图片尺寸对应的 token 映射 |

正常完成时，`generation.json` 中的 `stop_reason` 为 `"eos"`，`generated_tokens` 为 `4169`。
程序会检查视觉 token 流，再进行图像解码。

## 检查文本分词

如果只想查看提示词的 token，可以加上 `--prepare-only`，不加载模型权重：

```bash
uv run --locked python examples/xiaomi_u0/run_xiaomi_u0.py \
  --checkpoint-dir "$U0_CHECKPOINT" \
  --prompt "A studio photograph of a ceramic teapot on a wooden table." \
  --output-dir ./outputs/u0-prepare \
  --prepare-only
```

这个命令保存输入 token 数组、尺寸映射和准备记录，不需要图像解码器的权重。
查看完整命令行参数：

```bash
uv run --locked python examples/xiaomi_u0/run_xiaomi_u0.py --help
```

## 支持的配置

示例在单张 GPU 上处理一个提示词，生成固定的 64 × 64 视觉码网格，再解码为 1024 × 1024 图片。
token 生成使用 BF16、FlashInfer 分页注意力和无文本条件的 CFG，scale 为 3；原生解码器使用模型发布的 FP32 权重。
运行时关闭 CUDA Graph。当前示例不支持并发请求、其他图片尺寸或视频。

## 验证结果

GPU 检查使用 NVIDIA Thor、Torch 2.11.0、CUDA 13.0 和 512 MiB FlashInfer 工作区。
上面的三个提示词均采样到 EOS，输出完整的 4169 个 token，并解码为 1024 × 1024 RGB 图片。

固定 token 历史的回放覆盖 81 次预测，6279 次激活比较通过余弦相似度 `>=0.99`、相对 L2 误差 `<=0.05` 的检查。
首个视觉预测（step 7）的 logits 与独立 BF16 参考实现对比如下：

| Logits | 余弦相似度 | 相对 L2 误差 |
| --- | --- | --- |
| 有条件分支 | 0.9999767 | 0.0071404 |
| 无条件分支 | 0.9998077 | 0.0199978 |

两个分支的 top-1 token 均与参考实现相同。该次预测的采样分布 TV 为 `0.03753`。

解码器对照使用一组保存的视觉码，297 个被比较的参数与参考一致，15 个选定节点通过 `atol=1e-3, rtol=1e-4`。
最终 FP32 像素通过同样的容差，平均绝对误差 `<=1e-5`；转为 8 位后的最大像素差 `<=1`。

15 项 CPU 测试全部通过，其中包括缩小版解码器的 62 个输出对照。数值比较覆盖这里说明的固定历史和保存的视觉码。
